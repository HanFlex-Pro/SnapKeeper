# SnapKeeper 탐지 기준

상태: 확정 · 최종 수정: 2026-11-03

**아래 기준값은 모두 샘플 사진으로 보정하기 전의 임시값입니다.** 실제 값은 `lib/core/thresholds.dart`에서 한곳에 관리하고, 값을 바꾸면 이 문서도 함께 고칩니다.

## 1. 공통 입력

- 긴 변 1024px로 축소하고 EXIF 회전을 적용한 픽셀
- 파일 SHA-256, 크기, 해상도, EXIF

해상도가 다른 사진도 같은 기준으로 비교하기 위해 축소한 이미지로 분석합니다.

## 2. 탐지 규칙

### 완전 동일 (v0.2)

- **규칙:** 파일 크기와 SHA-256이 모두 같음
- **표시 이유:** "파일 내용이 완전히 같음"

계획에서는 크기가 같은 파일만 해시하려 했습니다. v0.2부터 pHash 계산을 위해 모든 파일을 읽으므로, 해시도 모든 파일에 계산합니다.

### 거의 동일 (v0.2)

- **pHash:** 32×32 흑백 이미지에 DCT를 적용하고 저주파 8×8 계수로 만든 64비트 값
- **규칙:** 아래를 모두 만족
  - 해밍 거리 2 이하
  - 가로세로 비율 차이 1% 이하
  - 평균 색의 채널별 차이 12 이하 (색 보정본 제외)
  - 평균 채도 차이 10 이하 (흑백 변환본 제외). 채도는 픽셀별 (최대 채널 − 최소 채널)의 평균입니다. 채도가 낮은 사진은 흑백본과 평균 색 차이가 10에 그쳐 평균 색만으로는 구분되지 않았습니다.
  - 밝기 표준편차 6 이상 (단색처럼 평탄한 이미지끼리 우연히 일치하는 것 방지)
- **비교 대상:** 완전 동일 그룹은 추천 사진 한 장만 비교합니다. 같은 사진이 두 그룹에 나오지 않게 하기 위해서입니다.
- **그룹:** 기준을 만족하는 사진끼리 연결해 묶습니다. 기준이 엄격해 연결이 길게 이어질 가능성은 낮지만, 그룹 안의 가장 먼 두 사진은 해시 차이가 2보다 클 수 있습니다.
- **검색:** 해시를 3개 구간으로 나눠, 한 구간 이상 일치하는 사진끼리만 비교 (10만 장에서 전체 비교를 피함)
- **표시 이유:** "보이는 내용이 거의 같음 (해시 차이 N)"

### 캡처 이미지 (v0.3)

- **규칙:** 카메라 EXIF(제조사·모델)가 없고, 아래 중 하나를 만족
  - 파일명에 `screenshot`, `screen shot`, `screen_shot`, `스크린샷`, `화면 캡처`, `화면캡처`, `capture` 포함, 또는 `scr_`로 시작 (대소문자 무시)
  - 바로 위 폴더 이름이 `Screenshots`, `Screenshot`, `스크린샷`
  - PNG이면서 해상도가 흔한 휴대폰·모니터 화면 크기와 일치 (가로·세로 방향 모두). 목록은 `lib/core/quality.dart`
- **표시 이유:** "카메라 정보 없음 + 파일명이 캡처 형식" / "+ 캡처 폴더" / "+ PNG, 화면 크기 1170×2532"
- **알려진 위험:** 메신저로 받은 사진, 웹에서 받은 PNG 이미지처럼 카메라 정보가 없는 사진이 화면 크기와 같으면 후보가 됩니다.

### 저화질 (v0.3)

- **규칙:** 총 픽셀 수 0.5MP 미만이고 **카메라 EXIF가 없음**
- **표시 이유:** "640×480 (0.31MP), 기준 0.50MP 미만"
- **카메라 사진 제외:** 오래된 디지털카메라 사진은 해상도가 낮아도 소중할 수 있어 제외합니다. 주 대상은 메신저로 받아 압축된 사진입니다.

### 초점 불량 (v0.3)

- **선명도:** 이미지를 8×8 타일로 나눠 타일별 라플라시안 분산을 구하고, 그중 최댓값을 사용
- **규칙:** 선명도 40 미만, 평탄한 이미지 제외
- **표시 이유:** "선명도 12, 기준 40 미만"
- **근거:** 배경이 흐린 사진도 피사체 타일은 선명하므로 후보에서 빠집니다.
- **크기:** 분석용 축소 이미지(긴 변 1024px)에서 계산합니다. 긴 변이 1024px보다 작은 사진은 키우지 않으므로 같은 기준으로 비교되지 않습니다. 이런 사진은 대개 저화질 후보로 따로 잡힙니다.
- **알려진 위험:** 하늘, 바다, 야경처럼 원래 세부 묘사가 적은 사진. 노이즈가 많으면 선명도가 높게 나와 놓칠 수 있습니다.

### 비슷한 사진 (v0.4)

- **규칙:** 촬영 시각순으로 정렬해 아래를 모두 만족하면 같은 그룹
  - 그룹 첫 사진과 촬영 시각 차이 60초 이하
  - 그룹 첫 사진과 pHash 해밍 거리 12 이하
  - 두 사진 모두 위치 정보가 있으면 거리 100m 이하
- **대표 비교:** 연속한 사진끼리가 아니라 그룹 첫 사진과 비교해, 조금씩 다른 사진이 끝없이 이어져 묶이는 것을 막습니다.
- **촬영 시각이 없는 사진:** 그룹에 넣지 않습니다.
- **베스트 컷:** 선명도가 가장 높은 사진, 같으면 해상도가 높은 사진
- **표시 이유:** "N초 간격, 구도 유사"
- **한계:** 눈 감음이나 표정은 평가하지 않습니다. pHash 정확도가 부족할 때만 ML 임베딩을 추가합니다.

## 3. 남길 사진 추천 (동일·거의 동일)

1. 해상도가 가장 높은 사진
2. 같으면 촬영일(없으면 수정일)이 가장 오래된 사진
3. 같으면 경로가 가장 짧은 사진

추천일 뿐이며 사용자가 바꿀 수 있습니다.

## 4. 공통 제외

- "보관"으로 표시한 사진은 후보에서 제외합니다.
- 분석에 실패한 사진은 후보에 올리지 않습니다.
- 한 사진이 여러 분류에 해당하면 각 분류에 모두 표시하고, 삭제하면 모든 분류에서 사라집니다.

## 5. 정확도 측정

샘플 사진은 저장소 밖에 둡니다. 정답은 폴더 이름으로 정합니다.

```text
샘플/캡처/  샘플/저화질/  샘플/초점불량/  샘플/정상/
```

품질 분류(v0.3)는 아래 명령으로 잽니다. 사진은 읽기만 합니다.

```sh
flutter test tool/evaluate_quality.dart --dart-define=SAMPLES=/경로/샘플
```

- **정밀도:** 후보 중 `정상` 폴더가 아닌 사진의 비율입니다. 캡처 사진이 저화질로도 잡히는 것은 지워도 되는 사진이라 오탐으로 세지 않고, "다른 분류"로 따로 보여 줍니다.
- **재현율:** 그 분류 폴더의 사진 중 후보로 잡힌 비율입니다.
- **함께 출력:** 오탐과 놓친 사진 목록(크기, 카메라, 선명도), 초점불량·정상 폴더의 선명도 분포. 기준값을 정하는 데 씁니다.

목표값은 PRD 9장을 따릅니다. 비슷한 사진(v0.4)은 그 버전에서 그룹 정답 형식을 정합니다.

| 분류 | 목표 정밀도 | 측정 정밀도 | 측정 재현율 | 측정일 |
|---|---|---|---|---|
| 완전 동일 | 100% | - | - | - |
| 거의 동일 | 99% 이상 | - | - | - |
| 캡처 | 90% 이상 | - | - | - |
| 저화질 | 90% 이상 | - | - | - |
| 초점 불량 | 90% 이상 | - | - | - |
| 비슷한 사진 | 80% 이상 | - | - | - |
