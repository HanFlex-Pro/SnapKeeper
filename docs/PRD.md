# SnapKeeper PRD

상태: 확정 · 최종 수정: 2026-11-03

## 1. 문제

스마트폰과 디지털카메라로 사진을 쉽게 찍게 되면서 사진이 직접 정리하기 어려울 만큼 쌓였습니다. 그 결과 다음 문제가 생깁니다.

- 기기 저장 공간이 부족해집니다.
- 다시 보고 싶은 사진을 찾기 어렵습니다.

## 2. 사용자

- 사진이 수천 장 이상 쌓여 있지만 직접 정리할 시간이 없는 일반 사용자
- 첫 사용자는 개발자 본인입니다. 공개 여부는 v1.0 전에 결정합니다.

## 3. 제품 원칙

1. **삭제는 항상 사용자가 결정합니다.** 앱은 후보를 제안만 합니다.
2. **삭제는 되돌릴 수 있어야 합니다.** 영구 삭제하지 않고 OS 휴지통으로 옮깁니다.
3. **사진은 기기 밖으로 나가지 않습니다.** 서버와 클라우드 분석을 쓰지 않습니다.
4. **탐지 이유를 보여 줍니다.** 사용자가 이유를 보고 판단할 수 있어야 합니다.
5. **오탐을 줄이는 쪽을 우선합니다.** 지워도 되는 사진을 일부 놓치더라도, 소중한 사진을 후보로 올리는 일을 줄입니다.

## 4. 기능 요구사항

### F1. 이미지 뷰어

- 폴더를 선택하면 하위 폴더까지 포함해 사진을 썸네일 목록으로 보여 줍니다.
- 사진을 크게 보고 이전/다음으로 이동할 수 있습니다.
- 파일명, 경로, 크기, 해상도, 촬영일, 카메라 정보를 표시합니다.

### F2. 동일 이미지 탐지

- 파일명이 달라도 내용이 같은 파일을 묶습니다.
- 인코딩만 다르고 보이는 내용이 같은 이미지는 "거의 동일"로 구분해 표시합니다.
- 그룹마다 남길 사진 하나를 추천합니다. 해상도가 가장 높은 것, 그다음 가장 오래된 것 순입니다.

### F3. 소장 가치가 낮은 사진 탐지

| 분류 | 판단 근거 |
|---|---|
| 캡처 이미지 | OS 메타데이터(모바일), 카메라 EXIF 없음 + 파일명·해상도 규칙(데스크톱) |
| 저화질 | 픽셀 수가 기준 미만 |
| 초점 불량 | 사진에서 가장 선명한 영역도 기준 미만 |
| 비슷한 사진 | 앵글·구도가 비슷하고 촬영 시각·위치가 가까움. 그룹에서 가장 좋은 컷 추천 |

### F4. 검토와 삭제

- 분류별로 후보를 모아 보여 주고, 각 후보에 탐지 이유를 표시합니다.
- 사용자가 고른 사진만 휴지통으로 옮기며, 그 전에 장수와 확보될 용량을 확인받습니다.
- 그룹의 모든 사진을 삭제하려 하면 경고합니다.
- "보관"으로 표시한 사진은 다시 추천하지 않습니다.
- 휴지통을 쓸 수 없는 위치(네트워크 드라이브 등)의 파일은 삭제하지 않고 실패 사유를 알려 줍니다.

### F5. 스캔

- 스캔 결과를 저장해 다음 스캔에서는 추가·변경된 파일만 처리합니다.
- 스캔 중에도 앱을 계속 쓸 수 있고, 중단하면 이어서 진행할 수 있습니다.

## 5. 화면 흐름

```text
폴더 선택 → 라이브러리(썸네일) ⇄ 사진 상세(이미지 + 정보)
                 │
                 └→ 스캔 → 정리 요약(분류별 장수, 확보 가능 용량)
                              │
                              └→ 분류별 검토 → 삭제 확인 → 휴지통 이동 → 결과 요약
```

모바일에서는 폴더 선택 대신 사진 보관함 권한을 요청합니다.

## 7. 제외 범위

v1.0까지 만들지 않습니다.

- 동영상과 RAW 파일 분석
- 사진 편집, 앨범 관리, 태그, 검색
- 클라우드 백업, 동기화, 계정
- 자동 삭제와 예약 정리
- 얼굴 인식

## 8. 세부 정책

2026-11-03 확정.

| 주제 | 정책 |
|---|---|
| 지원 형식 | JPEG, PNG, HEIC, WebP. Windows의 HEIC는 디코딩되지 않아 분석에서 제외하고 사유를 표시하며, v0.5 설계에서 지원 방법을 다시 검토 |
| 클라우드 전용 사진 | 기기에 내려받지 않은 사진은 분석에서 제외 |
| Live Photo | 사진과 영상을 하나로 취급 |
| RAW+JPEG 쌍 | RAW는 분석하지 않고, 쌍인 JPEG를 검토할 때 함께 표시 |
| 편집본과 원본 | 동일 이미지가 아니라 비슷한 사진으로 분류 |
| 언어 | 한국어. 공개를 결정하면 영어 추가 |

## 9. 성공 기준

M0 측정과 샘플 사진 평가 결과에 따라 조정할 수 있습니다.

| 항목 | 목표 |
|---|---|
| 완전 동일 탐지 정밀도 | 100% |
| 거의 동일 탐지 정밀도 | 99% 이상 |
| 캡처·저화질·흐림 탐지 정밀도 | 분류별 90% 이상. 흐림은 2026-11-06 측정에서 미달(약 60%)로, ML 재도전 전까지 주의 문구와 함께 제공 |
| 비슷한 사진 그룹 정밀도 | 80% 이상 |
| 처리 규모 | 10만 장에서 사용 가능 |
| 재스캔 | 변경 없는 사진은 다시 분석하지 않음 |
| 안전 | 사용자가 고르지 않은 파일의 이동·변경 0건 |
| 개인정보 | 외부 네트워크 전송 0건 |

**제품 목표:** 개발자 본인이 실제 사진 폴더를 이 앱으로 정리해 용량을 확보하고, 삭제 결과에 불안을 느끼지 않는 것입니다.

## 10. 위험 요소

| 위험 | 대응 |
|---|---|
| 소중한 사진을 후보로 제안 | 휴지통 이동, 사용자 확인, 탐지 이유 표시, 보수적인 기준값 |
| 대량 사진 처리 속도 | 재스캔 캐시와 Isolate. M0에서 실측 후 필요하면 네이티브 분석으로 교체 |
| Windows HEIC 디코딩 | M0에서 실패 확인. 분석에서 제외하고 v0.5 설계에서 다시 검토 |
| 모바일 삭제 제약 | 삭제 시 OS 확인 창이 표시될 수 있음. 해당 버전 설계에서 구체화 |
